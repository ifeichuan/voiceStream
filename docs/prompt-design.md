# SpeakMore Prompt 设计说明

## 当前 Prompt 位置

当前用于 `pi --mode rpc` 的提示词硬编码在：

- `src-tauri/src/pi_rpc.rs`
- 常量名：`PROMPT_TEMPLATE`

应用会把语音转写结果填入：

```text
<raw>
{text}
</raw>
```

然后通过 RPC 发送给 pi。

## 设计目标

当前 Prompt 的目标不是“聊天回复”，也不是“Prompt 优化器”，而是：

> 将原始语音转写内容整理成可直接使用的中性文本。

具体要求：

- 纠错
- 删除语气词
- 去除冗余和噪音
- 补齐断句和标点
- 保持原意
- 输出简短、清晰、自然
- 可直接粘贴发送、记录或写入文档

## 风格方向

参考了 Type4Me 的模式设计思路，以及对 Typeless 组织方式的抽象理解，但没有直接照搬：

- 不做强 Markdown 风格
- 不做聊天回复风格
- 不做“AI 助手在回答你”的感觉
- 更接近中性、可直接落地的最终文本

目标风格：

- 中性
- 简洁
- 弱结构化
- 直接可用
- 像整理后的成品，而不是模型回复

## 当前 Prompt 的核心策略

### 1. 保留原意与原句风格

- 不添加原文没有的新信息
- 不改变事实、要求、时间、对象和结论
- 尽量保留原句的语气、态度、确认感、迟疑感与节奏
- 优先少改写，而不是强行优化成另一种表达

### 2. 只做最小必要纠错

- 修正明显识别错误
- 修正常见同音误识别
- 修正明显漏字、重复词、严重语序异常
- 如果原句已经自然可用，则尽量原样保留

### 3. 谨慎去口语化

不是机械删除所有口语成分，而是只删除明显无意义的噪音词与识别残留。

例如以下内容通常应该保留其表达意味：

- 好的好的
- 哎我觉得还是继续写吧
- 那就这样吧

因此当前策略是：

- 删除明显无意义的停顿噪音
- 保留有表达作用的语气、确认、转折、迟疑和态度

### 4. 提升可读性

- 补齐必要标点
- 自动断句
- 让文本更顺，但不过度改写
- 不扩写成解释性文本、总结性文本或聊天回复

### 5. 弱结构化

仅在内容本身明显是以下类型时才结构化：

- 步骤
- 任务
- 并列事项
- 待办项

否则默认保持：

- 自然段
- 自然短句
- 原本句式

## 明确避免的方向

Prompt 明确避免以下输出倾向：

- 聊天口吻
- “好的，下面是……”
- 总结腔过重
- 强 Markdown 样式
- 标题/代码块/解释性前后文
- 不必要扩写

## 为什么这样设计

之前的实现更接近“Prompt 优化器”，容易把输入扩写成较长说明文本。

这不适合语音输入法场景，因为语音输入法更需要：

- 快速
- 直接
- 可粘贴
- 少解释
- 少格式负担

因此当前版本把目标改成“文本整理助手”，强调：

- 纠错
- 去口语化
- 去冗余
- 中性成文

## 后续可继续优化的方向

如果后续体验仍不稳定，可以继续细化为多种模式：

### 保守模式

- 尽量少改
- 只纠错、断句、删语气词

### 标准模式

- 纠错 + 去冗余 + 轻结构化

### 强整理模式

- 在不改变原意的前提下做更明显压缩和重组

也可以进一步按场景拆分：

- 普通文本输入
- 会议记录
- 待办整理
- 命令式输入
- 正式书面表达

## 当前结论

当前 Prompt 已不再是“生成高质量 Prompt”的方向，而是：

> 将语音转写整理成简短、清晰、自然、可直接使用的中性文本。
